## 🔄 關鍵數據流

### 1. 食物識別流程

```
圖片 → VLM → ['apple', 'rice', 'chicken']
```

### 2. 營養查詢流程

```
食物名稱 → NutritionCalculator
           ├─ TFND: apple → 52 kcal ✅
           ├─ TFND: rice → 130 kcal ✅
           └─ USDA: chicken → 165 kcal ✅

結果: {'apple': 52, 'rice': 130, 'chicken': 165}
```

### 3. RAG 推薦流程

```
當前餐點 + 歷史記錄 → Retriever → 結構化上下文
                                    ↓
                               LLM Prompt
                                    ↓
                            Gemini 生成建議
```

## 🆚 與原始流程圖的差異

| 項目        | 原始流程圖  | 實際架構                 |
| ----------- | ----------- | ------------------------ |
| VLM 後續    | 直接到 USDA | 到營養查詢協調器         |
| 資料源      | 只有 USDA   | TFND → USDA → LLM (三層) |
| 資料庫      | 未顯示      | SQLite 存儲層            |
| Coordinator | 一個        | 兩個（營養/推薦）        |
| LLM 角色    | 只生成推薦  | 推薦 + 熱量估算          |
| Retriever   | 位置不明確  | 在存儲層和 LLM 之間      |

## 💡 架構設計原則

### 1. **分層架構**

- 視覺層 (VLM)
- 資料層 (TFND/USDA/LLM)
- 存儲層 (SQLite)
- 檢索層 (Retriever)
- 生成層 (LLM)

### 2. **Fallback 機制**

- 每個關鍵模組都有降級方案
- TFND → USDA → LLM → 0
- Gemini → 規則引擎

### 3. **RAG 架構**

- Retrieval: 從資料庫檢索相關歷史
- Augmentation: 格式化為 prompt
- Generation: LLM 生成建議

### 4. **模組化設計**

- 每個模組職責單一
- 易於測試和維護
- 支援未來擴展
