## 🎤 口說稿

### 【開場】(15 秒)

大家好，今天要為各位介紹我們的專題作品：**食物營養推薦模型**。

這是一個整合了視覺辨識、資料檢索、和大型語言模型的智能系統，能夠自動追蹤使用者的飲食並提供個人化建議。

讓我先從系統架構開始介紹。

---

### 【流程圖說明】(30 秒)

**[指向流程圖]**

我們的系統採用**分層架構設計**，資料流向如下：

1. **使用者輸入層**：使用者上傳食物照片到 Discord

2. **VLM 視覺辨識層**：使用 `image_processor.py`，整合了 Gemini Vision 和 Azure Computer Vision 兩種模型來識別食物

3. **營養查詢層**：透過 `nutrition_calculator.py` 查詢營養資訊，這裡有三層 fallback 機制：

   - 優先查詢台灣食品資料庫 TFND
   - 找不到則查詢美國 USDA 資料庫
   - 都找不到時使用 LLM 估算熱量

4. **資料存儲層**：`data_storage.py` 將所有記錄儲存到 SQLite 資料庫

5. **RAG 檢索層**：當需要推薦時，系統會從資料庫檢索使用者的歷史記錄

6. **推薦生成層**：`recommendation_engine.py` 整合歷史資料和當前餐點，使用 Gemini LLM 生成個人化建議

7. **Discord 輸出**：最後透過 `discord_bot.py` 將結果回傳給使用者

整個系統由 `main.py` 統一管理和啟動。

---

### 【程式碼架構】(30 秒)

接下來介紹 `src` 資料夾內的主要檔案：

**[展示程式碼結構]**

- **`main.py`**：程式進入點，負責啟動 Discord bot 和設定日誌

- **`discord_bot.py`**：Discord 機器人的核心，處理使用者互動，實作了三個主要指令：

  - `/analyze`：分析食物照片
  - `/recommend`：生成飲食建議
  - `/history`：查詢歷史記錄

- **`image_processor.py`**：視覺辨識模組，包含：

  - `analyze_image_with_gemini()`：使用 Gemini Vision
  - `analyze_image_with_azure()`：使用 Azure CV
  - 自動 fallback 機制

- **`nutrition_calculator.py`**：營養查詢模組，實作：

  - `_query_tfnd_database()`：查詢台灣資料庫
  - `_query_usda_api()`：查詢 USDA API
  - `_estimate_calories_with_llm()`：LLM 估算熱量

- **`data_storage.py`**：資料庫操作模組，提供：

  - `store_meal()`：儲存餐點記錄
  - `get_previous_meals()`：取得今日前序餐點
  - `get_past_days()`：取得過去幾天統計
  - `get_history()`：查詢完整歷史

- **`recommendation_engine.py`**：推薦引擎，包含：
  - RAG 檢索邏輯
  - Prompt 模板設計
  - `get_recommendation()`：生成建議

## 💬 常見問題準備

### Q1：為什麼選擇 Discord 作為介面？

**A**：Discord 有完善的 Bot API、支援圖片上傳、使用者基數大，且開發快速。未來可擴展到 LINE、Telegram 等平台。

### Q2：如何確保營養資訊準確？

**A**：我們使用三層 fallback 機制：TFND（台灣官方資料）→ USDA（國際標準）→ LLM 估算，並標示資料來源讓使用者判斷。

### Q3：AI 建議的依據是什麼？

**A**：系統使用 RAG 架構，檢索使用者的歷史飲食記錄（今日前序餐點、過去幾天趨勢），結合當前餐點資訊，由 Gemini LLM 分析後生成個人化建議。

### Q4：系統的回應速度如何？

**A**：視覺辨識約 3-5 秒，營養查詢 2-3 秒，AI 建議生成 5-8 秒，總計約 10-15 秒完成整個流程。

### Q5：如何處理辨識錯誤？

**A**：系統使用雙模型驗證（Gemini + Azure），且使用者可以在後續手動修正記錄。未來會加入信心度顯示。
